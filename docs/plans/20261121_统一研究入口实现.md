# 统一研究入口：数据、工具、方案与执行

本次按已确认的顺序实现统一数据入口、工具及结果契约、AI 方案规划和统一运行管理。基线为 fbde14e，开发分支 feature/unified-research-entry。

## 数据与执行归属

BioFlow 的账号、项目、资源权限与 SQLite 继续作为唯一业务记录。新增 research_records / research_events 保存不可变数据版本、方案版本、任务、结果和产物。原始文件复用现有 assets 登记，不建立第二套文件库。导入 CSV、TSV、TXT、Excel 或记录型 JSON 时，明确角色、单位、矩阵方向、工作表和标识列，保留读取设置、来源与规范化文件哈希。

YanJi 统计方法作为随项目携带的计算源码接入，通过独立 Python 3.12 子进程运行。引擎目录中的数据库仅保存任务内部的输入与中间结果映射，不承担平台的用户、项目或任务生命周期；其中的数据可从 BioFlow 输入快照重建。API 进程不导入其科学计算环境。

## 统一契约

- 工具：ID、版本、说明、输入要求、声明的命名输出和参数 schema。
- 方案：目标、数据版本列表、输入哈希快照、步骤与依赖、参数、研究设置、确认指纹。
- 结果：工具及版本、状态、方法、指标、警告、证据、产物和输入来源。
- 产物：不透明 ID、文件名、内容哈希、大小、所属步骤及数据版本。

已登记固定工具可组成流程，已有结果效应图直接消费上传的统计结果。动态程序执行与论文生成继续由独立模块承担，不在本次统一队列中执行任意代码。

## 方案与执行

手动步骤和 AI 设计方案共用校验与确认路径。AI 只生成候选方案；用户核对后以指纹确认，执行前重新校验数据哈希和方法前提。编辑方案创建新版本。规划缺少输入时返回待补充问题，不创建运行任务。

一个具备文件锁的独立 worker 原子领取 SQLite 队列任务，逐步骤启动可取消子进程。运行事件持久化，页面关闭不影响任务。取消终止当前任务自己的进程组；服务恢复将遗留运行标记为 interrupted。恢复时核对输入和成功产物，复用仍有效的成功步骤，重跑其余步骤。产物同时登记到统一研究结果和现有资料库。

## 前端

数据分析主页面提供数据上传、已有资料登记、数据版本预览、工具选择、方案生成和编辑、确认执行及运行记录。保留历史流程入口。默认新建任务从矩阵或结果表进入。

## 部署

执行 deploy/setup_research.py 创建 runtime/research-python。应用服务配置：

```
BIOFLOW_RESEARCH_PYTHON=/absolute/project/runtime/research-python/bin/python
BIOFLOW_RESEARCH_AUTOSTART=1
BIOFLOW_RESEARCH_MODEL_URL=http://127.0.0.1:11441/v1
BIOFLOW_RESEARCH_MODEL=qwen3:14b
BIOFLOW_RESEARCH_MODEL_KEY=local
```

模型地址与凭据通过部署环境提供，不写入用户产物。首次验证使用独立运行目录和预览端口，不切换公共主站。
